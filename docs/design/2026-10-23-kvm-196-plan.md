# KVM 1.96.0 : hôtes, inventaire, cycle de vie (plan de réalisation)

Conception : `2026-10-23-hyperviseurs-kvm.md`. Cette version livre la déclaration des hôtes, l'inventaire en lecture et les gestes de cycle de vie, en CLI et dans la console.

## Contraintes communes

- Python 3.11, **bibliothèque standard seulement** dans `bin/` (pas de module `libvirt`). `virsh` est lancé **sur l'hôte** par SSH.
- `ssh` assemble ses arguments en une ligne de commande interprétée par le shell distant : **chaque argument distant passe par `shlex.quote`**. Un nom de VM ne doit jamais pouvoir injecter une commande.
- Options SSH : `-o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes -o UserKnownHostsFile=<fichier épinglé> -o IdentitiesOnly=yes -i <clé> -p <port>`, plus `ControlMaster=auto`, `ControlPath=<état>/ssh/cm-<nom>-<hash>` (hash court de l'utilisateur, de l'adresse et du port, pas `%C` : ssh lie d'abord `<chemin>.<16 caractères>`, le chemin final doit tenir en 90 octets), `ControlPersist=60`, et `stdin` fermé. `kvm_host.close_master()` ferme cette connexion à l'ajout et au retrait d'un hôte. Jamais `accept-new` pour un hôte KVM.
- Identifiants en anglais, commentaires en français, textes d'interface dans les cinq langues de `web/static/js/i18n.js`.
- Contenu public (docs, CHANGELOG, commits) : ni tiret cadratin ni flèche Unicode, aucune mention d'outil d'IA, pas de `Co-Authored-By`.
- Sécurité web : `@requires_auth` sur tout, `@_rate_limit("N/minute")` sur toute mutation, noms d'hôte contrôlés par `kvm_decl.NAME_RE`, aucun chemin de clé ni secret dans une réponse.
- Protocole des scripts : progression sur stderr en `STEP_EVENT|<id>|<status>|<message>`, sortie `--json` sur stdout, codes de sortie 0 (réussite), 1 (échec), 2 (usage).
- Tests en tableau, un cas par chemin d'erreur, une mutation volontaire au moins pour prouver qu'un test détecte.

## Tâche 1 : bibliothèque `kvm_host` et déclarations `kvm_decl`

Fichiers : `bin/lib/kvm_decl.py`, `bin/lib/kvm_host.py`, `tests/api/test_kvm_decl_196.py`, `tests/api/test_kvm_host_196.py`. Jeux d'essai réels : `tests/fixtures/kvm/` (relevés sur un hôte openSUSE, libvirt 12.7.0).

`kvm_decl` (calqué sur `bin/lib/cluster_decl.py`) :
- `NAME_RE`, `decl_dir(state)`, `load_all(state) -> list[dict]`, `load(state, name) -> dict`, `write(state, decl)` (écriture atomique, 0600, répertoire 0700, chemins relatifs au répertoire d'état), `remove(state, name)` (supprime aussi la clé et le fichier d'empreinte de l'hôte), `resolve(state, path)`.
- Schéma : `name`, `address`, `port` (22), `user`, `ssh_key`, `known_hosts`, `uri` (`qemu:///system`), `labels` (dict). `check_decl()` refuse un nom invalide, une adresse vide, un port hors 1..65535, une URI qui n'est pas `qemu:///system` ou `qemu+...`.
- `scan_host_key(address, port, runner=subprocess.run) -> list[{"type","line","fingerprint"}]` par `ssh-keyscan -p` puis `ssh-keygen -lf -` (empreintes `SHA256:...`).

`kvm_host` :
- `class KvmError(Exception)` avec `kind` parmi `unreachable`, `hostkey`, `auth`, `denied`, `notfound`, `timeout`, `failed`, classé depuis le code de sortie et stderr de ssh/virsh (stderr réels à reproduire dans les tests : `Host key verification failed`, `Permission denied (publickey`, `Connection refused`, `Connection timed out`, `failed to get domain`, `authentication unavailable` / `Permission denied` de libvirt).
- `ssh_argv(decl, state, remote_argv) -> list[str]` (contrat ci-dessus, `shlex.quote` sur chaque élément distant).
- `class VirshHost(decl, state, runner=subprocess.run, timeout=30)` : `virsh(*args, timeout=None) -> str` ; `batch(commands) -> dict[str,str]` qui lance plusieurs commandes virsh en **un seul** appel SSH, séparées par des marqueurs, et rend la sortie de chacune (un échec d'une commande n'efface pas les autres : sa sortie porte l'erreur).
- Analyseurs purs, testés sur les jeux d'essai : `parse_nodeinfo`, `parse_nodememstats`, `parse_list_all` (nom, état, id), `parse_dominfo` (persistant, démarrage automatique, état), `parse_domain_xml` (nom, uuid, vCPU, mémoire en Kio, épinglage CPU présent ou non, machine, micrologiciel, disques `{target, device, type, source, format, bus}`, cartes `{type, source, mac, model}`, affichages `{type, port, listen, autoport}`), `parse_domstats_raw` (par domaine : état, temps CPU, mémoire, vCPU, octets réseau et disque), `parse_pool_list_details`, `parse_vol_list_details`, `parse_net_list`, `parse_net_xml`.
- `host_inventory(host) -> dict` : un appel `batch` qui rend le résumé de l'hôte (nom, CPU, mémoire totale et libre, version libvirt et QEMU) et la liste des VMs avec leur état ; `vm_detail(host, name) -> dict`.

## Tâche 2 : CLI `bin/harvester-kvm.py`

Fichiers : `bin/harvester-kvm.py`, `tests/api/test_kvm_cli_196.py`.

Sous-commandes (argparse, `--json`, `--state-dir` par défaut `HARVESTER_OPS_STATE_DIR`) :
- `host scan --address A [--port P]` : empreintes de l'hôte.
- `host add --name N --address A [--port P] --user U --ssh-key FICHIER --fingerprint SHA256:... [--label k=v ...]` : refuse si l'empreinte donnée ne correspond à aucune clé relevée ; enregistre la clé (0600) et la ligne d'empreinte épinglée, puis fait le test de connexion.
- `host test N` : SSH, `virsh version`, droits sur l'URI, `qemu-img --version`, écoute VNC des VMs. Rend un résultat par point.
- `host list`, `host remove N`.
- `inventory [--host N]` : inventaire d'un hôte ou de tous (en parallèle).
- `vm list [--host N]`, `vm show --host N --name D`.
- `vm start|shutdown|reboot|destroy|suspend|resume --host N --name D [--timeout S]` : émet les étapes, suit l'état réel jusqu'à l'état attendu (`shutdown` : jusqu'à `shut off` ; `reboot` : retour à `running`), délai réglable (120 s par défaut pour `shutdown`), et à l'échéance un échec qui propose l'arrêt forcé.

Tests : faux `runner` qui rejoue les jeux d'essai et les stderr d'erreur ; argv exact construit ; noms piégés (`a;rm -rf /`, `$(id)`, espaces) qui restent un seul argument côté distant.

## Tâche 3 : console

Fichiers : `web/app.py`, `web/templates/index.html`, `web/static/js/kvm.js` (et fichiers voisins si besoin), `web/static/js/i18n.js`, `web/static/css/style.css`, tests `tests/api/test_kvm_routes_196.py`, `tests/e2e/test_kvm_196.py`.

- Routes : `GET /api/kvm/hosts` (résumé de tous les hôtes, en parallèle, `@shared_read`), `GET /api/kvm/hosts/<name>` (inventaire : VMs, pools, volumes, réseaux), `GET /api/kvm/vms` (toutes les VMs), `POST /api/kvm/hosts/scan`, `POST /api/kvm/hosts` (déclaration, clé envoyée en multipart, passe par `harvester-kvm.py host add`), `DELETE /api/kvm/hosts/<name>`, `POST /api/kvm/hosts/<name>/test`, `POST /api/kvm/vms/<host>/<vm>/<geste>`. Toute mutation en action suivie par `_cli_action` avec `check_busy=False`. Un hôte injoignable rend son erreur classée (`kind`) sans faire échouer les autres.
- Menu : groupe **KVM** dans la barre latérale avec Hôtes, Machines virtuelles, Stockage, Réseaux (motifs existants : `.tab-group`, `.card`, `.badge`, fenêtres `.modal-overlay`, bulles d'aide, `escapeHtml` avant tout `innerHTML`, suivi par `VMActions.follow`).
- Fenêtre « Déclarer un hôte » : adresse et port, relevé des empreintes, choix explicite de l'empreinte à épingler, utilisateur, clé privée, étiquettes, test de connexion affiché point par point.
- Vue des VMs : filtres (hôte, état), tri, menu d'actions par VM avec les six gestes, confirmation intégrée à la page pour l'arrêt forcé.
